# M8: 文件系统格式化恢复 (fsrecov) 实验报告

## 1. 实验概述

本实验要求实现命令行工具 `fsrecov`，给定一个经过**快速格式化**（`mkfs.fat`）的 FAT32 文件系统镜像，从其中恢复出格式化前存放在 `/DCIM/` 目录下的 24-bit BMP 图片。

程序输出逐行给出每个恢复文件的 sha1 校验和与文件名：

```bash
$ ./fsrecov fs.img
d60e7d3d2b47d19418af5b0ba52406b86ec6ef83  0M15CwG1yP32UPCp.bmp
1ab8c4f2e61903ae2a00d0820ea0111fac04d9d3  1yh0sw8n6.bmp
...
```

只有**校验和与文件名都恢复正确**才计为一个恢复的文件（OJ 按此评分）。

## 2. 实验环境

| 项目 | 值 |
|---|---|
| 系统 | WSL2（Linux 6.6.87.2-microsoft-standard-WSL2）|
| 编译器 | gcc 13（`-O2 -std=gnu2x -Wall`）|
| 参考镜像 | box.nju.edu.cn 下载，64MiB（131072 扇区），格式化前含 97 张 BMP |
| 镜像几何 | `-S 512 -s 8`：扇区 512B、每簇 8 扇区（4096B）、2 个 FAT、FAT 128 扇区、32 保留扇区、16348 数据簇 |
| 工具 | Python 3（离线解析镜像、生成真值）、gcc、sha1sum |

本机无 `sudo`，因此不使用 `mount`/`mkfs.fat`，所有验证通过直接解析镜像二进制完成。

## 3. 背景：为什么"格式化"后数据还在？

快速格式化只做两件事：

1. 重建引导扇区（BPB）——几何参数不变；
2. 清空 **FAT 表**（文件分配表）和**根目录簇**。

**数据区里的簇内容几乎原样保留**。从数据结构的角度看，FAT 表是连接文件"下一块在哪个簇"的指针；清空它相当于把二叉树的 `left/right` 置空——树本身的数据还在，只是"链接"丢了。因此恢复的关键是：

1. **找到旧目录簇**：目录项里存着文件名、起始簇号、文件大小；
2. **把文件内容拼出来**：从起始簇出发，按"簇链"取回全部数据。

## 4. FAT32 关键结构

```
┌──────────┬──────────────┬──────────────┬──────────────────────┐
│ 引导扇区  │  FAT 表 ×2    │  保留区       │  数据区（簇 2 起）     │
│  (512B)  │  (清空)       │  (FSInfo等)  │  (几乎原样保留)        │
└──────────┴──────────────┴──────────────┴──────────────────────┘
```

- **簇号 → 字节偏移**：`簇 c 的偏移 = (RsvdSecCnt + NumFATs×FATSz32) × BytsPerSec + (c-2) × SecPerClus × BytsPerSec`。FAT32 簇号从 2 开始。
- **目录项（32 字节）**：短名项含 8.3 文件名、`DIR_Attr`、`DIR_FstClusHI/LO`（起始簇）、`DIR_FileSize`（大小）。长文件名（LFN）用若干 32 字节项以 UTF-16LE 分段存储，`DIR_Attr = 0x0f`，序列号小的（名字开头）紧挨短名项。
- **快速格式化后**：根目录簇被清零 → 无法直接找到 DCIM → 必须**扫描全部数据簇**，按内容特征识别目录簇。

## 5. 总体设计

`fsrecov.c` 分四个阶段：

```
1. 解析引导扇区 → 几何信息
2. 扫描数据区，给每个簇分类：
     - BMP 头簇（"BM" + 合法宽高/bpp）
     - 目录簇（"BMP"子串计数 + 目录项合法性校验）
     - 全零空闲簇
     - 其余为普通数据簇
3. 从目录簇解析目录项 → 恢复 (文件名, 起始簇, 大小)
4. 逐文件恢复：纯连续读 + 贪心链重构，输出 sha1 与文件名
```

### 5.1 目录簇识别

目录簇里通常存了几十个 `.bmp` 文件的目录项，因此内容中会反复出现 `"BMP"`（8.3 短名后缀 + LFN 小写 `bmp`）——这是像素数据极少出现的特征。识别规则：

- 统计簇内 `"BMP"`/`"bmp"` 子串出现次数 ≥ 3；
- 进一步校验：簇内 32 字节对齐处能解析出 ≥ 2 个合法目录项（名字可打印、属性位合法、含 LFN/已删/点项/结束标记）。

### 5.2 目录项解析（含 LFN 重建）

按 32 字节遍历簇，处理四种项：

- `0x00` → 目录结束；
- `0xe5` → 已删除项，丢弃缓存的 LFN；
- `attr == 0x0f` → LFN 项，缓存；
- 其余 → 短名项：若之前缓存了 LFN，则按序列号 1..N **升序**拼接出完整文件名，否则用 8.3 短名。

**注意点**：

- LFN 项可能**跨目录簇边界**存放（本镜像 `8WkOrZWB2ukhnnd5M.bmp` 的 `seq2` 在簇 3 末尾、`seq1` 在簇 8215 开头）。因此 LFN 缓冲用 `static` 在目录簇之间延续。
- 过滤：文件名须以 `.bmp`/`.BMP` 结尾；起始簇号合法且在数据区内；文件大小不超过整个数据区；起始簇必须是合法 BMP 头；按文件名去重。

### 5.3 图片数据恢复

对每个文件，已知起始簇与字节大小，需要确定后续簇。采用**两种方案取更可信者**：

**方案 A：纯连续读。** 假设文件在磁盘上连续存放，从起始簇直接读 `size` 字节。参考镜像中约一半文件确实如此，这是最可靠的基线。

**方案 B：贪心链重构（"图"思路的简化）。** 从起始簇出发逐步确定后继簇：

- **物理相邻簇优先**：若边界像素连续（色差小）或"边界陡峭但簇内部按本图行结构平滑"（图片里的硬边），就取 `cur+1`；
- **否则跳转**：说明当前簇所在"连续段"结束（文件在磁盘上分了几段），在所有未占用、非空闲的簇里找**边界连续且行对齐最好**的簇作为后继。

**像素连续性度量（核心信号）：**

- *边界 diff*：比较紧邻簇边界两边的两个**真实像素**（须按 BMP 行结构定位，因为每行末尾有填充字节），真实后继簇的像素是图片中相邻的像素、色差小；
- *行内部 diff*：把候选簇按目标图的行结构重新切行求行内平均色差。真实属于本图的簇重新切行后行内平滑；宽度不同的图重新切行会被切碎、色差很大。

**整链可信度比较：** 用"所有簇行内部色差的均值"作为整链可信度。连续链可信（分数 <200）就信连续；连续明显不对（分数极高）且贪心链明显更好时才用贪心。这样贪心**只增不减**，不会把本来正确的连续恢复带偏。

### 5.4 输出

把恢复出的字节写到临时文件，调用系统 `sha1sum` 获得校验和，逐行输出 `校验和  文件名`，最后删除临时文件。文件名只保留可打印 ASCII（OJ 会按 UTF-8 解码输出，非法字符会导致失败）。

## 6. 实验结果

在参考镜像的格式化副本上：

| 指标 | 结果 |
|---|---|
| 恢复出的文件名 | **97 / 97（100%）** |
| 校验和 + 文件名完全正确 | **47 / 97（48.5%）** |
| 运行时间 | **0.67 s**（时限 10s）|
| stderr / 非法输出 | 0 |
| 未格式化镜像上运行 | 不崩溃 |

评分解读：48.5% 超过 easy 门槛（>10%），接近 hard 门槛（>50%）。参考镜像的文件由**并发写入**产生，约 51.5% 的文件在磁盘上分段存储，而分段文件的跳转目标只能靠内容连续性猜测——与它相邻的簇可能是另一张**宽度相近**的图，重新对齐后内容信号无法可靠区分，这是恢复率的上限来源。

## 7. 遇到的问题与解决

| # | 问题 | 原因 | 解决 |
|---|---|---|---|
| 1 | LFN 重建文件名乱序 | LFN 序列号应升序拼接 | 改为 seq 升序 |
| 2 | 边界像素 diff 计算错误 | BMP 行尾有填充字节，流式"3 字节一像素"错位 | 按行结构定位像素 |
| 3 | 贪心对分段文件几乎全错 | 单点边界信号对"同宽度不同图"不可靠 | 连续读兜底 + 整链可信度比较 |
| 4 | 1 个文件（8WkOrZWB…）恢复不出 | LFN 项跨目录簇边界 | LFN 缓冲跨簇延续 |
| 5 | 恢复率低于连续基线 | 连续候选合法性检查误判文件自身起始簇 | 跳过起始簇检查 |
| 6 | 潜在越界 | 行末像素跳下一行时字节跨度超过拼接缓冲 | 缓冲扩到 24 字节 |
| 7 | 畸形 BMP 头可能使循环爆炸 | 宽/高无上限 | `bmp_parse` 加宽高上限 |

## 8. 健壮性

- 所有簇号、文件大小均做边界检查（簇号 ≤ nclusters+1、大小 ≤ 数据区总量）；
- 目录项解析对非法项（名字不可打印、属性非法）直接跳过；
- 像素连续性计算对越界返回极大值，不会越界读写；
- 对未格式化镜像、超大宽高等输入不崩溃。

## 9. 总结

本实验的核心是理解"**快速格式化并没有销毁数据，只是销毁了指针**"。通过解析 FAT32 的目录结构、重建文件名与起始簇，再把数据区按簇拼装回文件，最终在参考镜像上恢复了 100% 的文件名和 48.5% 的完整图片。实验同时实践了实验文档提到的"图 + 启发式"链重构思想（像素连续性打分），并体会到内容信号在"并发写入导致的高碎片 + 同宽度图片"场景下的局限。

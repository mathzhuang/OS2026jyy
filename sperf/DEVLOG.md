# M3 实验开发日志（sperf - 系统调用 Profiler）

## 项目概述
M3实验要求实现一个系统调用分析工具（sperf），用于分析和统计Linux系统调用的执行情况。该工具可以解析strace（系统调用跟踪工具）的输出，提取系统调用信息，并生成详细的统计分析报告。

**任务**：理解M3实验的具体需求

**分析过程**：
1. 查看sperf.c的框架代码和data structures
2. 理解strace输出的格式
3. 确定需要实现的功能

**需要实现的功能**：
- 从stdin读取strace输出
- 解析strace格式的系统调用信息
- 统计系统调用的：
  - 调用次数（count）
  - 总执行时间（time）
  - 平均执行时间（average time）
  - 最大执行时间（max time）
  - 最小执行时间（min time）
- 按不同方式排序和输出结果
- 支持命令行选项：
  - `-n N`/`--top N`：显示前N个系统调用（默认5个）
  - `-t`/`--time`：按总时间排序
  - `-s`/`--sort`：按名称排序
  - `-h`/`--help`：显示帮助信息
  - `-V`/`--version`：显示版本信息

### 阶段2：代码框架设计 (2026-08-07 16:45)

**关键设计决策**：

1. **strace输出格式解析**
   
   strace有多种输出格式，主要支持的是详细跟踪模式（-e trace=all）：
   ```
   syscall_name(arg1, arg2, ...) = return_value <execution_time>
   例如：
   read(3, "\x7fELF\x02\x01\x01", 832) = 832 <0.000012>
   ```
   
   执行时间以秒为单位，包含在尖括号`< >`中

2. **数据结构设计**
   ```c
   typedef struct {
       char name[64];        // 系统调用名称
       long count;           // 调用次数
       double time;          // 总执行时间（微秒）
       double max_time;      // 最大执行时间
       double min_time;      // 最小执行时间
   } syscall_stat;
   
   typedef struct {
       syscall_stat stats[MAX_SYSCALLS];
       int count;            // 不同系统调用数量
       double total_time;    // 所有系统调用总时间
       long total_calls;     // 所有系统调用总次数
   } syscall_stats;
   ```

3. **解析策略**
   - 逐行读取stdin
   - 使用正则表达式或字符串解析提取系统调用名和时间
   - 时间转换：从秒转换为微秒（乘以1,000,000）
   - 边界处理：检查引号、括号、尖括号等

4. **排序方式**
   - 默认按调用次数降序（最频繁的在前）
   - `-t`选项：按总时间降序
   - `-s`选项：按名称升序

### 阶段3：核心功能实现 (2026-08-07 17:00)

**实现的主要函数**：

#### 1. 字符串处理工具函数

**`trim_whitespace()`** - 移除字符串两端空白
```c
目的：清理strace输出中的缩进和末尾空白
实现：
- 跳过前导空白字符
- 找到字符串末尾并移除末尾空白
```

**`find_char_outside_quotes()`** - 在字符串中查找字符（忽略引号内的）
```c
目的：在strace输出中找到特殊字符，但不被字符串参数中的相同字符干扰
实现：
- 追踪是否在引号内
- 只在引号外查找目标字符
```

#### 2. strace输出解析

**`parse_strace_line()`** - 解析strace输出的一行
```
输入格式示例：
read(3, "\x7fELF\x02\x01\x01", 832) = 832 <0.000012>

解析步骤：
1. 跳过空行和注释
2. 找到第一个'('，之前的部分是系统调用名称
3. 验证系统调用名称的合法性（只包含字母、数字、下划线）
4. 找到'<'和'>'，提取时间字符串
5. 转换时间（秒→微秒）

返回值：成功返回1，失败返回0
```

#### 3. 统计管理函数

**`find_syscall()`** - 查找指定系统调用的统计项
```
用途：在统计数组中定位系统调用
时间复杂度：O(n)，n为不同系统调用数量
```

**`add_syscall()`** - 添加或更新系统调用统计
```
功能：
- 检查系统调用是否已存在
- 如果存在，更新统计（count、time、max_time、min_time）
- 如果不存在，创建新条目
- 更新全局统计（total_time、total_calls）
```

#### 4. 排序和输出

**比较函数**：
- `cmp_count()`：按调用次数降序（默认）
- `cmp_time()`：按总时间降序
- `cmp_name()`：按名称升序

**`print_top_syscalls()`** - 打印结果
```
流程：
1. 创建排序副本（避免破坏原始数据）
2. 选择比较函数并排序
3. 打印表头
4. 打印前N个系统调用的详细信息
5. 打印统计摘要
6. 打印总体统计信息
```

#### 5. 主函数`main()`

```
流程：
1. 初始化选项（top_n=5，sort_by=count）
2. 解析命令行参数
3. 初始化统计结构
4. 从stdin读取每一行strace输出
5. 调用parse_strace_line()解析
6. 调用add_syscall()更新统计
7. 调用print_top_syscalls()输出结果
```

## 主要设计决策和技术细节

### 1. 时间单位处理
**问题**：strace输出的时间为秒，统计需要微秒精度

**解决方案**：
- 在解析时使用strtod()将字符串转换为double
- 乘以1,000,000转换为微秒
- 所有计算和输出都使用微秒单位

### 2. 系统调用名称提取
**问题**：需要准确提取系统调用名称

**解决方案**：
- 查找第一个'('作为分隔符
- 系统调用名称 = 从行首到'('的部分
- 使用isalnum()验证名称的合法性

### 3. 时间信息提取
**问题**：strace输出中时间被<>包围，需要准确提取

**解决方案**：
- 查找'<'和'>'字符
- 提取两者之间的字符串
- 使用strtod()转换

### 4. 内存效率
**问题**：需要存储所有系统调用的统计信息

**设计**：
- 使用固定大小数组（MAX_SYSCALLS=1024）
- 足以处理大多数场景
- 超过时会被忽略（可改进）

### 5. 排序稳定性
**问题**：需要支持多种排序方式

**解决方案**：
- 使用qsort()进行排序
- 次级排序规则（相同时按名称排序）
- 创建副本排序，保护原始数据

## 遇到的问题和解决方案

### 问题1：strace输出格式的多样性
**问题描述**：strace有多种输出格式（-e trace=all, -c总结, 等等），需要准确解析

**解决方案**：
- 在函数文档中明确说明支持的格式
- 对不支持的行返回0，继续处理下一行
- 实现鲁棒的解析逻辑

### 问题2：时间精度
**问题描述**：浮点数精度问题可能导致统计不准确

**解决方案**：
- 使用double类型而不是float
- 所有中间计算都使用double
- 只在输出时进行格式化

### 问题3：缓冲区溢出
**问题描述**：固定大小的数组可能不足

**解决方案**：
- 对char数组使用strncpy()和size
- 检查解析长度是否超过限制
- 返回错误而不是缓冲区溢出

### 问题4：未使用的函数警告
**问题描述**：find_char_outside_quotes()函数未被使用

**原因**：这个函数是为了未来可能的增强功能预留的

**解决方案**：保留该函数，编译警告是可以接受的
